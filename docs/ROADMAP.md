# 桌面视线悬浮层：工作大纲

Oct 15, 2026 · @shenzeyu

## 一、目标、范围与暂不做的事

目标：程序常驻后台，在笔记本内置屏幕的任何位置（不限于本应用窗口）实时显示视线效果，并通过日常点击无感地完成个人校准。基线是 v0.1.0（commit `291ea98`），按 M0 → M6 顺序推进，每个里程碑一个 PR。

**范围**

- 平台：Windows（Core Ultra 9 + RTX 5070）与 macOS（M5），同一份代码
- 屏幕：追踪只支持带摄像头的内置屏；M7允许投影镜像/扩展，外接屏不独立追踪
- 显示：透明、置顶、鼠标可穿透的悬浮层，显示注视圈和实时热力图
- 校准：九点校准保留为对照组（B 组）；主线是基于全局点击的隐式校准（C 组）
- 现有网页界面保留，继续用于九点校准和独立精度评估

**暂不做**

- 「跟着移动点看」的追随校准（仍属显式校准，不满足无感要求；只有 M4 实验证明点击样本覆盖不足时才重新考虑）
- 网页内容级热力图、浏览器插件
- 移动端部署、模型重训练与轻量化
- 卡尔曼等预测式滤波（M2 结果不够时再评估）
- 用眼睛点击、选择等眼控交互

## 二、总体架构

所有功能共用同一条坐标流；不同用途各取所需的版本，延迟与平滑的取舍只发生在悬浮层显示这一路。

&#91;embedded content: 系统架构 · 一条坐标流、四路输出\]

全局点击只用来生成校准样本，隐式校准的结果写回个人修正，影响下游所有输出。

| 模块 | 位置 | 说明 |
| --- | --- | --- |
| 公共核心 | `gaze_core/` | 采集、引擎、几何、滤波、眼跳检测、校准、录制、热力图；不依赖任何界面 |
| 网页界面 | `app.py` + `static/` | 保留：九点校准、独立评估、CSV 导出 |
| 桌面悬浮层 | `overlay.py` + `overlay/` | 新增：透明穿透窗口、托盘、快捷键、点击监听 |
| 离线工具 | `tools/` | 回放、滤波调参、隐式校准实验、会话热力图、相机标定 |
| 配置 | `config/` | 默认参数 + 每台设备的标定与屏幕尺寸 |
| 本地数据 | `data/`（不提交） | 录制会话、个人校准档案 |

## 三、给 Codex 的通用工作约定

每个里程碑开工前，先把本节作为固定指令交给 Codex（建议同时写进仓库根目录的 `AGENTS.md`）。

**代码与提交**

1. 每个里程碑单独开分支（如 `m0-recording`），完成后开 PR，不直接推 `main`
2. 小步提交：一次提交只做一件事；提交信息写清楚改了什么、为什么
3. 每个 PR 更新 `CHANGELOG.md` 和 `验证记录.md`：分「已验证」「未验证」两栏，并写明在哪台机器、哪个系统上验证
4. 新增的纯计算逻辑（滤波、眼跳检测、拟合、热力图累加、坐标换算）必须有单元测试；提交前全部测试通过
5. 可调参数一律放进配置文件（如 `config/default.yaml`），不写死在代码里

**数据与结论**

1. 绝不编造、估算或「预填」精度数字；没有实测就写「未验证」
2. 所有成绩标明分组：A 未个人校准 / B 九点校准 / C 隐式校准后，不混用
3. 精度评估和校准取样只用**未滤波、未裁剪**的原始输出；滤波只用于显示
4. 评估目标点永远不参与任何校准拟合

**隐私（硬性要求）**

1. 不保存、不上传任何摄像头画面或人脸图像
2. 全局输入监听只记录**鼠标按下的坐标、时间和按键类型**；绝不记录键盘输入、窗口标题、屏幕内容
3. 点击监听默认关闭，用户在托盘菜单中主动开启
4. 录制数据放在 `data/`，写进 `.gitignore`，不提交到仓库

**坐标约定**

- 统一使用内置屏的**归一化全屏坐标**：左上角为 (0, 0)，右下角为 (1, 1)，允许超出 \[0, 1\]（不裁剪）
- 换算成像素时一律用系统逻辑坐标（考虑 Windows 缩放和 Mac Retina），换算成厘米时只用实测屏幕尺寸
- 时间戳一律用单调时钟（`time.perf_counter_ns()` 或等价实现）

## 四、M0 引擎提速 + 原始数据录制与回放

**目标**：把引擎抽成网页和悬浮层都能调用的公共核心，压低延迟，并能完整录下原始视线流。后面的滤波调参、隐式校准实验、热力图都依赖这份录制。

**任务**

1. 新建公共包 `gaze_core/`，把 `engine.py`、`geometry.py` 移进去；`app.py` 改为从 `gaze_core` 导入，网页功能保持不变
2. 人脸检测改为视频跟踪模式：`mediapipe_static_image_mode = False`；丢失人脸后能自动重新检测
3. 推理设备自动选择：有 CUDA 用 GPU，否则 CPU；在验证记录里写明 Windows 机实际用的设备。RTX 5070 需安装支持 CUDA 12.8 的 PyTorch（cu128），写进安装指南
4. 新增 `gaze_core/capture.py`：采集线程和推理线程分开，中间只保留最新一帧（旧帧直接丢弃），不要排队
5. 新增 `gaze_core/recorder.py`：按 JSON Lines 格式录制会话到 `data/sessions/<日期时间>.jsonl`
   1. 第一行为会话信息：程序版本、系统、设备名、屏幕尺寸及是否实测、相机内参及来源（估计 / 标定）、推理设备、是否灰度
   2. 每帧一行 `frame`：采集时间、推理完成时间、是否有效、状态、原始归一化坐标、视线起点与方向、头姿角、视距、睁眼程度、推理耗时
   3. 事件行：`target`（评估/校准目标出现、切换）、`click`（M4 使用）、`calibration`（修正参数变化）
   4. 不含任何图像
6. 新增 `tools/replay.py`：读取录制文件，按时间顺序把帧送入任意处理函数（滤波、校准等），输出处理后的序列和指标
7. 网页界面加一个「录制」开关；九点校准和独立评估期间自动录制并写入 `target` 事件
8. 新增「跳点任务」：目标点在屏幕上随机跳动，每个点停留一段时间，用于 M2 测量抖动和延迟

**验收**

- [ ] 网页功能在两台机器上与 v0.1.0 一致（校准、评估、导出均正常）
- [ ] 两台机器各记录改动前后的实际帧率和推理耗时（写进验证记录）
- [ ] 录制 5 分钟后用 `replay.py` 回放，帧数、时间戳、坐标与录制时一致
- [ ] 录制文件中不含图像数据（加测试检查）

**不要做**：不要在这一步加滤波或修改显示逻辑；不要改变现有 CSV 导出格式。

## 五、M1 评估可靠性修正

**目标**：后面所有对比实验都要靠独立评估来判断好坏，所以先修正 v0.1.0 评估里会让数字失真的地方。

**任务**

1. **相机内参标定**：新增 `tools/calibrate_camera.py`，用 OpenCV 棋盘格标定，结果保存到 `config/devices/<设备名>.yaml`（内参 + 畸变系数 + 屏幕实测尺寸 + 摄像头相对屏幕位置）。引擎先读设备文件，没有才用估计值，并在录制和 CSV 中标明来源
2. **视距自检**：界面提示用户坐到尺子量好的 50 cm 处，对比程序估计的视距，偏差过大时提示重新标定或调整焦距
3. **评估点覆盖边缘**：评估点改为中央点 + 屏幕四角与四边附近的点，位置与九点校准点错开、顺序随机；CSV 里每个样本标注 `region = center / edge`
4. **按目标点统计**：除现有的逐帧统计外，增加「每个目标点取误差中位数」后的平均误差、P90、≤1.5 cm 和 ≤2 cm 占比；中央和边缘分开报告
5. **屏幕尺寸强制实测**：未勾选「尺寸已实测」时不输出任何厘米结果；去掉只适用于 Mac 的默认尺寸，改为从设备文件读取
6. **个人校准档案**：九点校准结果保存到 `data/profiles/<设备名>.json`（修正矩阵 + 来源 + 时间），供悬浮层读取；M5 的隐式校准写入同一文件

**验收**

- [ ] 两台笔记本各有一份标定好的设备文件
- [ ] 同一人在标定前后各做一轮 A 组评估，对比结果记入验证记录
- [ ] CSV 包含 region 字段；结果表同时显示逐帧和按目标点两种统计
- [ ] 新统计函数有单元测试

**不要做**：不要为了让数字好看而删掉边缘点或剔除大误差样本。

## 六、M2 滤波：One Euro + 眼跳检测 + 离线调参

**目标**：注视时点稳定不抖，视线跳开时立即跟上。参数用录制数据定量选定，不凭感觉。

**设计原则**

- 眼动是「注视—眼跳」交替：注视期间强平滑（延迟察觉不到），眼跳时重置滤波、直接跳到新位置
- 滤波只作用于实时显示；评估和校准取样用原始输出；热力图和报告用离线双向平滑（无延迟）
- 滤波只减抖动，不减偏差；不要用滤波参数去「修」精度

**任务**

1. `gaze_core/filters.py`：实现 One Euro 滤波（x、y 各一个），按真实时间戳计算帧间隔，支持 `reset(position)`；参数 `min_cutoff`、`beta`、`d_cutoff` 放配置文件
2. `gaze_core/fixation.py`：速度阈值法（I-VT）区分注视/眼跳。速度用厘米或角度每秒计算（借助屏幕尺寸和视距换算），并在很短的窗口内估计以压低噪声；输出每帧状态和注视段（起止时间、中心、时长）
3. 串接：原始坐标 → 个人修正 → 眼跳检测 → One Euro（眼跳时 reset）→ 显示。网页界面的显示改用这条链路，去掉 `app.js` 里的固定 0.65 / 0.35 平滑
4. 离线双向平滑函数，供 M6 会话热力图使用
5. `tools/tune_filter.py`：在 M0 「跳点任务」录制上扫描参数组合，对每组计算：
   1. 抖动：注视段内显示点的位置标准差（cm）
   2. 延迟：目标跳动后，显示点走完跳动距离 90% 所需时间（ms），和未滤波原始输出的同一指标相减，得到滤波引入的额外延迟
   3. 画「延迟—抖动」散点图，标出帕累托前沿；在拐点附近选默认参数
6. 选定参数后找 2–3 人主观试用，在拐点附近微调

**后续可选改进（待办）**

- [ ] 对比显示的未滤波点与滤波点采用一致样式（包括点大小和短轨迹）。
- [ ] 对比显示可互换两点颜色，减少颜色对主观判断的影响。
- [ ] 增加盲测模式，用于在不知道滤波条件的情况下比较响应与稳定性。

**验收**

- [ ] 单元测试：恒定输入收敛；阶跃输入在眼跳检测触发后立即到位；帧间隔不均匀时结果正确
- [ ] 报告中包含取舍曲线图、最终参数，以及滤波前后的抖动和额外延迟数值
- [ ] 评估 CSV 的误差仍来自原始输出（加测试检查）

**不要做**：不要引入卡尔曼等预测式滤波；不要对评估或校准数据做滤波。

## 七、M3 桌面悬浮层原型

**目标**：程序常驻后台，在内置屏任意位置显示注视圈，且不影响正常使用电脑。这一步平台相关的坑最多，**每个子任务都要在两台机器上分别验证**。

**技术选型**：PySide6（Qt），在 Python 内直接调用 `gaze_core`，不经过网页服务和 JPEG 传输。入口为 `overlay.py`，代码放在 `overlay/`。

**分两次 PR 实施（2026-10-20 用户确认）**

- **M3a，`m3a-overlay`**：先做可独立启动的最小穿透窗口与 Mac 验证说明，再接 CameraPipeline、`capture_ns` 驱动的 M2 显示链路、完整内置屏逻辑坐标、未校准注视圈、无人脸省电与权限指引。最简托盘只含显示/隐藏、暂停/恢复、退出；始终标明「未校准」，不加载任何个人档案。半径使用明确标为示意值的配置；本阶段没有 B 组核对结果。
- **M3b，M3a 实机验证通过后另开 PR**：悬浮层自己的全屏九点校准与快速精度核对，复用 evaluation / profiles；输出同网页口径的 A/B 逐目标汇总并写入数值录制。档案增加 `pipeline: web / python`，只自动加载匹配的 python 档案，手动加载 web 档案明确提示裁切/链路差异风险；网页矩阵不能假定可直接用于 OpenCV。最近有效 B 组核对结果用于圆环误差尺度；加入完整托盘与系统热键。
- **M3b 热键约束**：macOS 必须用 Carbon `RegisterEventHotKey`，Windows 必须用 `RegisterHotKey`；禁止监听全部键盘事件（例如 pynput 键盘监听），不需要也不申请「输入监控」权限。
- **M3b 本次拆分（用户批准）**：第一个 PR，分支 `m3b-calibration`，实现独立九点/核对、档案隔离与匹配、数值录制、B 核对半径、必要控制面板/托盘失效退路，以及异常恢复立即淡出。设备指纹仅含有意义的参数，不对 YAML 原文计算；校准/核对记录估计距离中位数，仅供分析，档案年龄仅显示、不自动过期。
- **M3b 第二个 PR（第一个 PR #8 已合并，从 main ba8943a 建立 m3b-controls）**：完整托盘与四类可配置系统热键；面板逐项显示注册失败，其他热键仍可用；`inference.num_threads` 兼容旧 cpu_threads、显式 MPS 不可用回 CPU、同输入 CPU/MPS 数值及耗时对比；新增 `inference.max_fps`，显示仍用 One Euro、不插值。根据 Mac 收尾实测，默认采用 `device: auto`（Mac 仍选 CPU）、`num_threads: 2`、`max_fps: 15`，Windows 待测，可用 local.yaml 覆盖；九点、补看和精度核对期间临时不限推理帧率，结束或中断后恢复任务前实际上限（默认 15）。对比包含 num_threads=2 与 4，并解释 PyTorch 限制不等于进程总线程数，分别实测 CPU/GPU/总线程和各线程来源，不预填结果。用户已报告的 Mac 结果见验证记录，未逐项报告及 Windows 实机路径保持未验证。
- **M3b 第二个 PR 追加（用户批准）**：`overlay.panel_on_start: auto / always / never`，macOS auto 等于 always，延迟仍打印托盘状态。九点后显示/录制校准点自身仿射残差；实测厘米超过 `overlay.calibration_redo_cm`（默认 2.0）时可只补看这些点，与原稳定样本合并、重新取点中位数后拟合，最多一轮；取消补看保留首次完整结果。未实测屏幕只报告逻辑像素，不套用厘米阈值。不引入非线性映射，不把拟合残差当作独立 B 组精度。
- M3a 不实现 M3b 功能；各阶段界面与可测试逻辑分离。下列任务中校准档案、误差核对半径、完整托盘和热键属于 M3b。

**任务**

1. **透明穿透窗口**：无边框、背景透明、始终置顶、不接收鼠标输入（Qt 的 `WindowTransparentForInput`）、不出现在任务栏；覆盖内置屏的完整几何区域
2. **macOS 全屏应用**：通过 pyobjc 设置窗口可加入所有桌面空间并显示在全屏应用之上（`canJoinAllSpaces`、`fullScreenAuxiliary`），**最先在 M5 上验证**。Windows 独占全屏（部分游戏）无法覆盖，写进已知限制
3. **坐标映射**：归一化坐标 → 内置屏 `QScreen` 的逻辑坐标；在 Windows 100% / 125% / 150% 缩放和 Mac Retina 下验证：屏幕四角的归一化坐标必须映射到屏幕四角
4. **注视圈**：半透明圆环；M3a 使用明确标注的配置示意半径，M3b 默认使用最近一次条件匹配的 B 组精度核对平均误差，无结果时用配置值；眼跳时直接跳转；眨眼或丢失时淡出，不显示错误位置
5. **系统托盘**：M3a 仅显示/隐藏、暂停/恢复、退出；M3b 增加当前模式（未校准 / 九点）、开始校准、精度核对、打开网页、录制开关
6. **全局快捷键（M3b）**：显示/隐藏、暂停；按键组合可在配置里修改，必须使用上述系统热键注册接口
7. **省电**：连续没有人脸时降低采集帧率，重新检测到人脸后恢复；暂停时完全释放摄像头（指示灯熄灭）
8. **权限检查**：首次启动检查摄像头权限，缺失时给出对应系统设置的中文指引
9. **读取校准档案（M3b）**：增加 pipeline 字段并隔离 web/python，启动与文件变化时只自动加载条件匹配的 python 档案；手动加载 web 档案需明确提示链路差异风险。M3a 不读取档案

**验收**

- [ ] 两台机器各连续运行 30 分钟无崩溃，并记录 CPU / GPU 占用
- [ ] 悬浮层开启时，下方应用的点击、拖动、滚动全部正常
- [ ] 在浏览器、代码编辑器、Mac 全屏应用上方均可见
- [ ] 缩放测试：四角映射正确（单元测试 + 实机截图）
- [ ] 快捷键、托盘各项功能可用；暂停后摄像头指示灯熄灭

## 八、M4 全局点击记录 + 隐式校准离线实验

**目标**：先不做实时功能，而是用录制数据回答一个问题：**日常点击能否代替九点校准，需要多少次点击？** 结论决定 M5 做不做、怎么做。

**任务**

1. `overlay/click_listener.py` 只处理鼠标按下：macOS 使用 NSEvent 全局监视器，并用仅鼠标按下的本地监视器标记本程序窗口；Windows 使用 `WH_MOUSE_LL` 的按下消息。平台实现隔离，绝不使用 pynput、键盘钩子或全键盘监听。只记录时间、内置屏全屏归一化坐标、按键类型及必要的时钟/排除字段；内屏外直接丢弃，不查询其他应用名称、窗口标题或内容。本程序控制面板、任务窗口等点击标记后排除，拖动只用按下位置。
2. 默认关闭，控制面板及托盘均可主动开关；面板持续显示状态和已 flush 的非排除/排除次数，暂停、失败、退出清理。当前 Mac 的 NSEvent 鼠标短测在辅助功能与输入监控均未授权时成功接收左/右键，未请求权限；不把该短测作为新增功能端到端验证，其他键与 Windows 待测。
3. **采集协议**（本轮先做本人在 Mac 上的数据，多人与 Windows 后续补充；人数不足三人不拒绝分析）：
   1. 默认重新九点，保存并激活后才开始。当前条件匹配的 Python 档案不足 300 秒时，用户可明确选择跳过；B 的矩阵、校准时间与年龄均写入录制，不静默复用旧档案。
   2. 自动开启或借用数值录制与点击采集，自然使用电脑 20–30 分钟。`click_session.max_fps` 默认 null（不限推理速度），结束后恢复正常上限（默认 15）；报告实际推理帧率，由采集期全部结果的 capture_ns（含无效帧）计算，不把配置值当实测值。
   3. 结束采集后提示独立全屏精度核对，末尾核对 raw 帧作为所有方法的公共测试集；精确记录选中的 frame_id / target_id 和取样配置。取消可重试或明确中止，不以半成品完成实验。
   4. 九点、点击、末尾核对及汇总在一个 JSONL 内，通过 experiment_id 界定；借用手动录制时保留其所有权，结束手动录制后写出 end。输入不完整时说明原因，不补造样本。
   5. 点击与 capture_ns 同属 perf_counter_ns：NSEvent.timestamp 用系统 uptime 映射，Windows 鼠标消息 time 结合 GetTickCount64 展开回绕后映射，均夹取单调时钟、复核偏移。不可可靠转换时改用回调收到时间，标明来源；未知延迟估计为 null，保留映射不确定度，不假设 Windows 毫秒单位等于毫秒精度。
4. `tools/implicit_calib_experiment.py`：
   1. **取样**：每次点击前窗口的未滤波、未裁剪 raw 中位数形成一个等权样本；窗口起止扫描，不预设答案。1 cm 内、500 ms 内的双击/连点按首按合并，两阈值可配置且不链式延长；原始录制不改写。
   2. **筛选**：有效帧比例、样本数/时间覆盖、M2 注视稳定性、头姿、位置离散；报告全部点击的剔除比例与互斥主原因，另列无脸/眨眼等帧诊断，稳健拟合离群率使用筛选后训练样本分母。
   3. **模型分级**：只修偏移（两个参数）→ 偏移 + 缩放 → 完整仿射
   4. **稳健拟合**：RANSAC 或 Huber 损失，剔除「点击时没在看」的样本；记录被剔除的比例
   5. **覆盖度**：统计样本落在屏幕 3×3 网格中的分布，退化/覆盖不足明确报告失败；仅做点击计数，不做 M6 注视热力图。
   6. **公平比较**：所有 A/B/C 使用同一批末尾核对原始帧并调用 evaluate()，逐目标中位数后等权汇总；中央/边缘、偏移和斜率同面板。A 为 raw，B 为开始时九点矩阵，C 独立从点击 raw 拟合，不叠加 B。窗口、三级模型和最近 N 只用点击训练数据的时间分块验证选择，不使用公共测试集挑选。
5. **输出报告**（`reports/implicit_calibration.md` + 图）：
   1. 主图按点击数 5、10、20、40、全部绘制独立核对误差，三级模型及 A/B 参考线；另比较最终完成的末尾核对开始前最近 N 分钟的点击。随机子集固定种子、配对重复，无放回，报告中位数与配置分位区间，不冒称人群置信区间。
   2. 分人、分机器、分中央/边缘报告，标明人数、机器数、完整会话数及外推限制；单人 Mac 也正常运行，不要求三人才能得出本会话结论。
   3. 点击前时间窗口的扫描结果和选定值
   4. 3×3 点击计数覆盖图；空白区域单独指出。输出同名 JSON/CSV、图和输入/代码/配置摘要，个人数据与报告被 Git 忽略，只有模板及代码提交。

**正式采集前固定判定规则（2026-10-21 登记，不再修改）**：在同一次末尾核对上，若训练阶段预选的「全部点击」C 整体平均误差 ≤ B，或预选「最近 N 分钟」C ≤ B，判为 M5 值得做；若两者均未达到，且两种完整 C 均比 B 差至少 0.5 cm（含边界），判为点击不能替代九点，M5 改为「九点 + 点击微调」；介于两者之间或缺少可比较结果时报告「证据不足」，需要更多数据。不用公共核对结果反选窗口、模型或 N，不达标也是有效结论。

## 十、M6 热力图与区域统计

**目标**：在悬浮层上实时显示视线集中的区域，并能对一段录制生成会话热力图和区域统计。

**前提说明**：桌面热力图反映的是「看了屏幕的哪个区域」，不是「看了什么内容」；窗口切换和页面滚动会让同一位置对应不同内容。界面和报告里都要写明这一点。

**任务**

1. `gaze_core/heatmap.py`：低分辨率网格累加器（网格大小可配置）。**按注视段累加，权重 = 注视时长**，不按帧累加；眼跳和无效帧不计入
2. 高斯核半径与当前误差尺度挂钩（和注视圈半径同一来源），不显示比实际精度更尖锐的热点
3. **实时模式**（悬浮层）：后台按指数衰减累加，半衰期可配置；默认按需查看，半透明色阶叠加；后台累加与查看使用独立开关
4. **会话模式**（离线）：`tools/session_heatmap.py` 读取 Python 录制，只取完整的悬浮层精度核对时段（含点击会话末尾核对），用 M2 的离线双向平滑 + 眼跳检测生成热力图；导出 PNG、网格 CSV、区域 JSON 和说明报告到 data/heatmaps/
5. **区域统计**：默认把屏幕分成 3×3 个区域，也可在配置里自定义矩形；输出每个区域的停留时间占比、首次注视时间、进入次数
6. 托盘增加「清空热力图」和「导出当前会话」

**M6 已确认的实施约定**

- 默认关闭，匹配 Python 九点后才允许默认开启；`heatmap.allow_uncalibrated: false`，强制开启持续标注未校准。
- 网格宽160、高度随完整逻辑屏比例；后台处理，默认display_mode=on_demand，开启只累加。Ctrl+Alt+H开关累加，heatmap_view默认Ctrl+Alt+V查看/隐藏，面板共用。view_update_hz默认1 Hz，continuous也用该速率；未查看时不生成/传递热图图片，不新增悬浮层重绘，隐藏转换仅清除一次旧图。update_hz保留为后台断帧检查速率。
- 半衰期 **60 秒**，最大不透明度 **0.4**；alpha_threshold默认0.15，按当前最大热量归一化，阈值以下全透明，从透明黄到红，无深色低端；小图平滑插值放大，圆环始终在上。显示阈值不改网格/区域数值，整图等比例衰减时相对色阶不变。
- 核尺度只由一个公共函数换算：实测屏幕上 **sigma = 圆环误差半径 cm**，优先最近匹配 B 核对均值，没有则配置示意值；未实测屏幕用圆环的逻辑像素示意值，不估算厘米。面板显示当前sigma数值、单位和来源。
- 按注视段时长累加；持续段预览可替换，不能重复结算。区域统计不衰减，实时网格指数衰减，导出分别注明单位。
- 热图专用边缘容差：中心到最近屏幕点的厘米/逻辑像素距离≤同源1 sigma时夹回并计入区域，超过才排除；角落按欧氏距离。实时/离线共用函数，edge_clamped_s与真正屏外outside_s分列，不改变原始、检测或校准/核对坐标。
- Python 录制增加可选矩阵版本与核尺度来源，旧文件按事件时间回退并说明对齐局限；不改变校准、核对或点击采集算法，不做 M5。
- 实施方案与性能预算见 `docs/m6-heatmap-design.md`；预算是验收目标，不是实测值。
