## 固定通过标准

1. **硬归属正确比例 ≥60%**：分母为八个指定注视窗口内所有有效、已确认的注视时长（含落在错误块及背景的有效注视），分子为归到提示块的时长。非注视、眨眼、无脸、屏外、断档、暂停、不确定区间不进该分母，必须逐类报告时长和有效覆盖率；不得仅以已命中 AOI 的时长为分母。全部无有效注视为未通过/数据不足。软归属另报，不替代硬门槛。
2. **场景切换检出率 100%（3/3）**：验收页滚动一次、切到另一页一次、切到另一应用一次；各自稳定 ≥1.5 秒，必须各产生新场景。检出允许最长 max_unstable_ms+采样周期；动态强制场景单独标记。小动画/时钟/鼠标移动不计指定变化，另外报告误切次数。
3. **自窗口残留为零**：固定受控底图上，让圆环、热力图、状态/录制提示、面板、弹出菜单、后创建的窗口持续可见，不调用 hide；应用原生过滤后这些测试标记残留像素=0。不能用肉眼“差不多”替代检查。过滤失败必须停止采集。
4. **进程树额外 CPU <单核10%**：同一相机/推理配置，先30秒关闭分析，再30秒开启分析，计算应用及 OCR 子进程 CPU 时间/墙钟时间×100 的平均值差；不能按整机核心数摊薄。OCR采集期受预算节流、结束后补跑。另列 WindowServer CPU，不混入 Python 进程数字。暂停/失败导致未完成采集的运行不算通过。
5. 测量并报告视线结果延迟增量、截图/回调耗时、OCR排队和处理耗时、30秒会话结束至整理完成的墙钟耗时；不预填结果或另设事后门槛。

## 一次约30秒引导

0–16秒：8个编号大块，每块2秒，前0.5秒为换点缓冲，后1.5秒用于上述注视正确率。
16–22秒：按提示滚动、切页、切应用（三次，每次约2秒）。
22–26秒：进入排除名单应用并返回；记录暂停区间，不截图。
26–30秒：暂停/恢复、结束。整理完成后检查数据与一键删除。

脚本自动保存提示时间、布局、真实操作时间、有效覆盖和各排除分母。实际用户未执行指定动作时记“步骤未执行”，不能伪造检出率。CPU关闭基线由工具另外自动采集，不占用户注视任务。权限若缺失仅需首次系统授权。
