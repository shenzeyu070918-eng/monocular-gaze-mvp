## Mac：原工作目录原地同步（不重新clone）

**仅远端改写确认推送成功后执行。** 本人选择保留原路径，避免破坏.venv绝对路径。`reset --hard`会丢弃已跟踪修改，也可能删除阻碍写入新tracked路径的未跟踪/忽略项；所以先备份并确认无路径碰撞，不能笼统承诺它绝不会动忽略文件。

先停止所有本项目进程，检查`git status --short`，把未提交工作保存为补丁/文件并核查本地分支已备份。示例私有备份位置在项目目录外：

```sh

mkdir -p "$sync_backup"
git bundle create "$sync_backup/local-refs.bundle" --all
git diff --binary HEAD > "$sync_backup/tracked.patch"
git ls-files --others --exclude-standard > "$sync_backup/untracked.txt"
```

继续复制实际存在的目录；下面仅展示本机原路径备份，不上传：

```sh
ditto .venv "$sync_backup/.venv"
ditto models "$sync_backup/models"
ditto data "$sync_backup/data"
ditto config "$sync_backup/config"
```

如有reports也复制；按untracked清单另备份其它文件，尤其目前两个`config/local.yaml.bak-*`。记录受保护文件SHA256与数量，核对备份可读，不能仅创建空目录即算成功。备份完成并确认已跟踪工作可丢弃后：

```sh
git fetch --prune origin
# 与本人批准的refs-before-after表核对origin/main完整SHA，再继续
git switch main
git reset --hard origin/main

# 需要继续M10时才同步该分支；现在仍暂停
git switch m10-report
git reset --hard origin/m10-report
# 其它需要保留的工作分支同理逐一对齐，不merge旧历史

```

如果本地分支不存在，改用`git switch --track origin/分支名`。旧本地分支refs不自动删除，不把它们再次推回；可按原备份清单检查需要同步的每一个分支。若tag发生变化，核对映射后逐tag用显式`+refs/tags/名称:refs/tags/名称`取回；不要无审阅地覆盖未备份的本地私人tag。
