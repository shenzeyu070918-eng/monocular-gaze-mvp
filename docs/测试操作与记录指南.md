# 视线实验台 v0.1.0：测试操作与记录指南

本轮目的：确认同学能在自己的笔记本上运行，建立未个人校准 A 与九点校准 B 的精度和稳定性基线，找出下一步优先解决的问题。主测试约 20–30 分钟；首次安装另计。

这是研究原型。当前 11,177,538 参数，设备几何使用估计内参；尚未达到最终轻量化要求，也尚未证明厘米级精度。目标点代表测试者按指令注视的位置，未使用专业眼动仪验证。

## 1. 安装与准备

1. 下载 GitHub 的 `v0.1.0` Release 源码并解压，按根目录 [README](../README.md) 安装、启动。
2. 用 Chrome 打开 `http://127.0.0.1:8765`。等待「模型就绪 · 本地运行」，点击「开启摄像头」，允许相机权限。其他同学需各自在本机启动；这个地址只指向当前电脑。
3. 使用内置摄像头和单块笔记本屏幕，浏览器缩放设为 100%。关闭占用摄像头的会议软件，接电源，关闭省电模式。暂不使用外接摄像头或外接屏作为主测试。
4. 用尺量出**发光显示区域**的宽、高，单位 cm；不量边框，不填写屏幕对角线。量出摄像头中心到发光区域上边缘的距离，填入「相机高于屏幕」；摄像头在上方为正数。焦距比例先保持默认 1，整组测试期间不调节。
5. 在「屏幕与相机参数」填写实测值，勾选「尺寸已实测」，点击应用内「全屏体验」。等窗口变化提示结束再开始校准或评估。看结果单位是否为 cm；若仍为 px，先导出保存并记录原因，不换算成厘米成绩。
6. 测试者编号用 P01、P02 等代号。复制 [测试记录模板](测试记录模板.md)，填写设备、版本、屏幕、光线、眼镜和距离。正常室内光照，面部均匀受光；主测试视距先固定约 50 cm，用尺量眼部到摄像头的直线距离，避免依赖页面的「估计视距」。
7. 先熟悉绿色注视点 1–2 分钟。正式评估时只看蓝色目标，不用点鼠标；保持自然睁眼，允许正常眨眼，尽量只转眼睛。不要为追着预测点而额外转头。

> 页面每次新评估只保留这一轮数据。下一轮评估、校准、切换输入或改变窗口尺寸前，必须先导出上一轮 CSV。校准参数只在当前页面内存中，刷新、重新开启摄像头或窗口尺寸变化会使它失效。已下载文件不会被清除。

## 2. 主测试：同一人、同一设备、同一条件

### A：未个人校准，连续 3 轮

1. 点击「暂停并关闭摄像头」，再点击「开启摄像头」，确认显示「未个人校准 · 几何参数为估计值」。不要点击「九点校准」。
2. 保持实测尺寸、全屏、50 cm、彩色输入，点击「独立评估」。依次注视蓝点中心，每点约 2.2 秒；预测点在评估时会隐藏。
3. 完成后先抄下未校准列的平均、中位、P90、≤1.5 cm / ≤2 cm 比例、有效跟踪率。点击「导出 CSV」，重命名为 `P01_color_50cm_A01.csv`。
4. 按相同操作做 A02、A03，每轮立即导出。轮间不移动屏幕，不调参数，不择优删除失败轮。

### B：九点个人校准一次，连续 3 轮

1. 点击「九点校准」，依次看蓝点中心，不用鼠标点击。若提示补样本，继续注视；若取消，记录失败原因与尝试次数，然后重试。
2. 成功后保持头部、屏幕和窗口位置，点击「独立评估」。目标位置与九点校准不同，评估不会更新校准参数。
3. 抄下两列结果和有效跟踪率，导出为 `P01_color_50cm_B01.csv`。B02、B03 沿用**同一次校准**；不要每轮重新校准。
4. B 轮 CSV 同时包含同一批帧的 A/B 误差，可以在相同测试输入下比较个人校准是否有效。单独 A 轮用于确认首次使用表现。

显示模式切回「未个人校准」只改变绿色点的显示，不删除已有校准。正式独立 A 轮按前面的重启摄像头步骤执行。B 轮 `calibration_id` 应相同，且不为 `none`。

## 3. 稳定性：校准后保持运行 10 分钟

沿用 B 的校准。开始计时，保持通常使用姿势，每分钟记一次跟踪状态、有效更新率、单帧处理时间和异常。第 0、5、10 分钟各运行并导出一次独立评估，命名为 `P01_color_50cm_stability_T00.csv`、T05、T10。

这 10 分钟不刷新、不重启、不重新校准；如确需恢复，记录发生时间、操作与原因。记录绿色点抖动、持续偏移、模型报错、摄像头断开、页面卡住等现象。偶尔眨眼显示「眨眼」本身是正常过滤行为。

页面「有效更新率」是最近 2 秒有效响应数除以 2；启动最初几秒偏低，不作为性能结论。「单帧处理」不包含完整采集与显示时间，不能记为端到端延迟。当前 CSV 没有完整 10 分钟性能日志，持续性能主要靠每分钟记录，注明这一限制。

## 4. 恢复与附加条件

完成主测试后分别试一次，单项进行，记录恢复是否需要重启：

| 操作 | 观察内容 |
|---|---|
| 自然眨眼，再短暂闭眼约 2 秒 | 是否暂停输出，睁眼后能否恢复 |
| 小幅左右转头，再回到原位 | 是否丢失、漂移、回正后恢复 |
| 离开画面约 3 秒，再回到原位 | 无人时是否停止产生有效坐标，返回后能否恢复 |
| 暂停并关闭摄像头 | 摄像头指示灯是否关闭 |

额外测试必须单独编号，不能混入主条件：

- **灰度**：先导出当前结果，开启「灰度输入对照」会清除校准。在同一 50 cm 条件下重复 A 三轮、校准一次、B 三轮。记录 `grayscale=true`。灰度是三通道复制输入，并非重新训练的灰度模型。
- **距离**：以后可在 25、40、60 cm 各做独立 A/B 会话。把「每个距离重新校准」和「沿用 50 cm 校准换距离」分开命名；后者检查校准是否随距离变化失效。
- **光照 / 眼镜**：每次只改变一个条件，分别记录。不要为了好成绩一边看结果一边调焦距或模型设置。调参实验单独存放，并用新测试轮验证。

## 5. 记录、统计与判定

至少 3 位同学，分别用 P01–P03。尽量包含一位戴眼镜者。每个人保留所有轮次和异常，不只提交最好的成绩；只完成部分测试也照实标记。

| 指标 | 记录与解释 |
|---|---|
| 平均 / 中位 / P90 误差 | 只统计稳定注视窗口内的有效帧；P90 表示 90% 有效样本误差不超过该值 |
| ≤1.5 cm、≤2 cm 比例 | 分母为有效样本数，同时报告有效跟踪率，防止过滤掉困难样本后成绩看似很好 |
| 有效跟踪率 | `valid=true` 行数 / 全部评估行数；CSV 会保留无效帧状态，不补写误差为 0 |
| 校准次数、失败轮 | 原样保留；取消或未完成的轮次也写进记录表 |
| 性能与恢复 | 10 分钟逐分钟记录；UI 处理时间和更新率分开记录 |

先分别汇总**每人每轮 A/B**，再汇总每人平均，最后对 3 人等权汇总。P90 不能简单平均各轮 P90 得到总体 P90；需要从有效误差样本重新计算。合并数据时保留测试者、条件、轮次；不要让高帧率同学因样本更多而主导跨人平均。

本轮建议采用以下门槛；这些是初步验收规则，需要团队采纳后固定，不能事后根据结果改低：

| 层次 | 建议判据 | 结论写法 |
|---|---|---|
| 工程 MVP | 至少 3 人各自完成启动、A/B、CSV 导出；各主测试轮有效跟踪率 ≥90%；10 分钟无崩溃或必须重启，稳定注视时每分钟观察的有效更新率 ≥15 Hz | 通过 / 未通过 / 证据不足；逐人记录，失败设备不隐去 |
| 个人校准的收益 | B 相比同帧 A 的误差是否下降，3 轮是否一致；本轮先报告真实数值，不把 B 的成绩用于声称免校准达标 | 有收益 / 无明显收益 / 变差，并列出数值 |
| 项目最终精度 | 无个人校准 A：25–60 cm，平均 ≤1.5 cm、≥70% 样本 ≤1.5 cm、≥90% 样本 ≤2 cm；≥3 人盲测，覆盖约定场景 | 当前测试只能提供部分证据，单一 50 cm 通过不能判整个范围通过 |
| 项目最终部署与资源 | <5M 参数、<1 GFLOPs、移动端、一周无感适应后平均 ≤1cm及无回退 | v0.1.0 未完成，不纳入本次工程 MVP 通过结论 |

当前评估只有应用测试区内的六个目标位置，尚未覆盖整屏四角、完整边缘、自由观看或所有恶劣工况；即使这批成绩达标，也应标记为**固定目标、固定坐姿的初测结果**。

## 6. 提交与归档

每人提交一个文件夹：

```text
P01_v0.1.0/
  测试记录.md
  P01_color_50cm_A01.csv
  P01_color_50cm_A02.csv
  P01_color_50cm_A03.csv
  P01_color_50cm_B01.csv
  P01_color_50cm_B02.csv
  P01_color_50cm_B03.csv
  P01_color_50cm_stability_T00.csv
  P01_color_50cm_stability_T05.csv
  P01_color_50cm_stability_T10.csv
```

灰度和额外条件加独立文件。原始 CSV 保留不改；表格填写错误时在记录中说明。把文件夹压缩后通过团队约定渠道交给项目负责人；默认不要把个人测试 CSV、人脸截图或视频放到公开 GitHub Issues。问题反馈可使用仓库的测试反馈模板，填写代号和不含个人信息的摘要。

负责人保留 `v0.1.0` 标签对应源码、依赖说明、模型摘要、指南版本、所有原始 CSV、测试记录和验收结论。GitHub Release 是可运行基线的归档，后续测试报告应另行补充；发布本身不代表项目精度验收通过。
